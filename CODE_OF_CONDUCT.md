# Code of Conduct — FieldSeal Suite

## Our standard

Be direct, technical and civil. Critique the artefact, not the person. Assume good faith
until evidence says otherwise, and say what evidence you used.

## Expected

- Use clear language; quote the command, version and output when reporting a problem.
- Respect confidentiality: never paste customer evidence, passphrases, private keys or
  personal data into an issue.
- Accept a “no” on scope: the trust contract is intentionally narrow.

## Not acceptable

- Harassment, threats, discrimination or sexualised language.
- Publishing a suspected vulnerability instead of using the private advisory.
- Doxxing, doxxing-adjacent “research”, or sharing another person's data.
- Removing attribution or licence notices in a contribution.

## Scope and enforcement

This applies to repository issues, discussions, reviews and project chat. Maintainers may
edit/remove content or close a thread; repeated or severe violations lead to a block. Security
reports are handled privately under `SECURITY.md`, not through this process.

## Contributor Covenant

This project follows the [Contributor Covenant](https://www.contributor-covenant.org),
version **2.1**. The sections above restate and specialise it for this project; where a
project rule is stricter than the Covenant, the stricter rule applies. The Covenant's
full text is the reference for anything not covered here.

## Enforcement contact

Enforcement reports go to the maintainers through the repository's private reporting
channel described in `SECURITY.md` (private security advisory) or, for conduct issues
that are not security issues, through the repository issue tracker addressed to the
maintainers. **No email address is published here on purpose** — an unmonitored address is
worse than none; the repository tracker is monitored.

## Attribution

This is a project-specific code of conduct aligned with Contributor Covenant 2.1, not a
legal document. It does not replace the operator's own workplace or jurisdiction rules.
