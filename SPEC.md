# FieldSeal Suite Specification

Version: 1.0
Status: Frozen — confirmed by the project owner on 2026-11-11 (Q1–Q6 accepted as written)
Algorithm: SHA256
Time format: ISO8601 UTC
Text encoding: UTF-8
Line endings: LF

> This document is the single contract source. The schema is frozen: no manifest field may be added, removed, or renamed.
> The CLI (Step 1) and the PWA (Steps 2/3) must use this document as their shared ruler.

---

## General rules

1. Every package is a standard ZIP archive.
2. Every package contains one `manifest.json` at the archive root.
3. Root hash: SHA256 over the `manifest.json` text (canonical form, no extra spaces, stable key order via `JSON.stringify`).
4. Auxiliary attachments (canvas snapshots, preview videos) do not enter the root hash; only the structured manifest plus original media participate in the hash tree.
5. This suite provides no legal guarantee and is not a qualified electronic signature.
6. Aegis is an external system; only the [root hash string] is pushed, never a file.

---

## Implementation conventions (clarifications; no new or changed manifest fields)

These rules remove ambiguity and keep CLI and PWA implementations identical. **They introduce no new fields, rename no fields, and change no value semantics.**

### C1 Hash string format

Every hash field is `sha256:` plus 64 lowercase hex characters and must match `/^sha256:[0-9a-f]{64}$/`.
Inputs are UTF-8 bytes (text) or raw file bytes (binary), read in streamed chunks; never load a whole file into memory (GB-scale video).

### C2 Stable serialization (canonical JSON)

- Recursively sort object keys by Unicode code point; arrays keep their original order.
- Use `JSON.stringify` semantics with no indentation, no extra spaces, no trailing newline, no BOM.
- `manifest.json` / `bundle-index.json` are written with this canonical text and LF newlines.

### C3 Self-reference handling (critical)

The manifest contains `rootHash`, so hashing the whole text directly is circular.
Definition: build `payload = shallow copy of the manifest with the rootHash key removed`, canonicalize it per C2, then hash:

```
rootHash = "sha256:" + hex(SHA256(UTF8(canonical(payload))))
```

Verification removes `rootHash` the same way, recomputes, and compares. Field names, counts, and values are unchanged; only the read view used for hashing is defined.
`bundle-index.json` follows the same rule for its `rootHash`.

### C4 Time

- `createdAt` / `signedAt`: `YYYY-MM-DDTHH:mm:ssZ`, UTC, second precision, no milliseconds, trailing `Z`, generated by code.
- `captureTsDevice`: device-local ISO8601 with a `+01:00` / `-05:00` offset; recorded only, **not a trusted time source** (documentation must state that device time can be altered).
- Non-UTC offsets must not appear in `createdAt` / `signedAt`.

### C5 File names

Archive entry names must match `/^[A-Za-z0-9][A-Za-z0-9._-]*$/`: no path separators, no `..`, no Chinese or special symbols; `.` is only for the extension (`photo.jpg` / `video.mp4` are valid).
`manifest.json` and `bundle-index.json` sit at the archive root; auxiliary attachments live under `aux/`.

### C6 ZIP writing

- All entries use STORE (method 0, no compression) so media bytes stay original and can be streamed.
- Implementations must support ZIP64 (> 4 GiB or > 65535 entries) for GB-scale video.
- Original media is never transcoded or re-encoded; manifest text is written per C2.

### C7 files[] and the hash tree

- Each `files[]` item must correspond to a real file at the package root; hash it byte-by-byte and compare.
- Files not listed in `files[]` (including everything under `aux/`) do not enter the evidence root hash tree.
- A declared file missing → `tampered`.
- An undeclared root entry (`manifest.json` / `bundle-index.json` / `aux/` excepted) → `tampered`, preventing smuggling.
- Signature and bundle packages have no `files[]`; their root entries are `manifest.json` + `aux/`, or `bundle-index.json` + child `.zip` files.

### C8 bundle items[].hash semantics

`items[].hash` is SHA256 over **all raw bytes of the child package ZIP** (streamed).
Recursive verification first compares child bytes, then verifies the child's own manifest and files per its spec.
`items[].type` is `evidence` | `signature-record`.

### C9 Auxiliary layer and canvasSnapshotHash

- The **code logic** in `pwa/helpers` (drawing engine, WebRTC sync, preview encoding) never enters hashing; deleting the helpers directory must leave verification fully functional.
- Helper output is bound only when it is an **explicitly declared manifest field**.
- Evidence packages: low-bitrate preview copies under `aux/` are forbidden from `files[]`, never enter the root hash tree, and must be marked "reference only, not the original evidence".
- Signature packages: `canvasSnapshotHash` is a defined structural field, part of the frozen record, bound by `rootHash` through the manifest; the snapshot file lives under `aux/`.
- Open item: see Q3 at the end.

### C10 pluginExtras

Exists only in CLI JSON / HTML report output; **never written into any manifest** and never enters the root hash.

### C11 Field strictness

For every manifest, the **required key set = the key set of the JSON example below**; no keys outside the example (`additionalProperties: false`).
Missing keys, extra keys, or wrong types are all `invalid_spec`.

### C12 100% hand-written code (project iron rule)

All source in this repository must be written line by line. Forbidden:

- Third-party npm / runtime libraries (including crypto, zip, pdf, drawing, templating, build tools).
- Copying, pasting, porting external project source or snippets, or vendored third-party source files.
- CDN / remote `<script>`, remote fonts, remote CSS/JS, online icon libraries, or a Service Worker fetching third-party scripts at runtime.
- Source produced by code generators / CLI scaffolding, third-party bundles, or minified/obfuscated blocks.
- Any `npm install`, `require` of a non-built-in module, or `import` of a file not hand-written in this repository.

**Only allowed**: calling **platform-native APIs** — capabilities shipped with the runtime, not considered "external code" under the project convention:

- Node.js built-ins: `fs`, `stream`, `crypto`, `zlib`, `path`, `util`, `process`.
- Browser-native Web APIs: WebCrypto (`crypto.subtle`), `CompressionStream`, `File` / `Blob` / `FileReader`, `MediaDevices`, Canvas 2D, `fetch`, `RTCPeerConnection`, Service Worker, `CacheStorage`.

Boundary note: SHA256 and the ZIP container are implemented through `crypto` / `zlib` / WebCrypto / `CompressionStream`, never by rewriting cryptographic or compression algorithms. If the owner requires even these primitives to be hand-written, that must be stated before freezing (see Q6).

Self-check: both CLI and PWA must provide a zero-external-code static self-check asserting the forbidden items above are zero (see `cli/test/TEST-CASES.md` §F).

## Package types

- `fieldseal-evidence-v0.1`: minimal evidence package, media hashes only.
- `fieldseal-evidence-v0.2`: full evidence package, media + GPS/note/tags all hashed.
- `fieldseal-signature-v0.1`: countersign frozen-record package.
- `fieldseal-bundle-v0.1`: super-bundle for evidence + signature packages.

### 1. fieldseal-evidence-v0.1 `manifest.json`

```json
{
  "spec": "fieldseal-evidence-v0.1",
  "packageId": "uuid-v4",
  "rootHash": "sha256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "createdAt": "2026-11-11T10:00:00Z",
  "files": [
    { "name": "photo.jpg", "hash": "sha256:xxx", "type": "image" },
    { "name": "video.mp4", "hash": "sha256:xxx", "type": "video" }
  ]
}
```

Types: `spec` string literal; `packageId` string (UUID v4, lowercase hyphenated); `rootHash` / `files[].hash` per C1; `createdAt` per C4; `files[].name` per C5; `files[].type` ∈ `image` | `video`.

### 2. fieldseal-evidence-v0.2 `manifest.json`

```json
{
  "spec": "fieldseal-evidence-v0.2",
  "packageId": "uuid-v4",
  "rootHash": "sha256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "createdAt": "2026-11-11T10:00:00Z",
  "captureTsDevice": "2026-11-11T11:00:00+01:00",
  "gps": { "lat": "52.5200", "lon": "13.4050" },
  "note": "On-site maintenance acceptance record",
  "tags": ["damage", "installation", "trade"],
  "files": [
    { "name": "photo.jpg", "hash": "sha256:xxx", "type": "image" },
    { "name": "video.mp4", "hash": "sha256:xxx", "type": "video" }
  ],
  "mp4SanityCheck": { "status": "ok", "note": "moov/mdat segment found" }

```

> `captureTsDevice`: device-local time (alterable; documentation must say so).
> `createdAt`: UTC standard time (generated by code).
> `mp4SanityCheck`: container sanity only; frames are never decoded.

Additional types: `gps.lat` / `gps.lon` are decimal **strings** (avoiding float serialization differences); `note` string; `tags` string array; `mp4SanityCheck.status` ∈ `ok` | `failed` | `skipped`, `note` string. `mp4SanityCheck` is informational; the CLI never decodes video.

### 3. fieldseal-signature-v0.1 `manifest.json`

```json
{
  "spec": "fieldseal-signature-v0.1",
  "packageId": "uuid-v4",
  "rootHash": "sha256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "createdAt": "2026-11-11T10:30:00Z",
  "linkedEvidenceId": "evidence-package-uuid",
  "linkedEvidenceRootHash": "sha256:xxx",
  "parties": [
    { "name": "Customer", "confirm": true, "signedAt": "2026-11-11T10:28:00Z" },
    { "name": "Technician", "confirm": true, "signedAt": "2026-11-11T10:29:00Z" }
  ],
  "canvasSnapshotHash": "sha256:xxx",
  "sealNote": "Both parties confirm acceptance with no objection"
}
```

> `linkedEvidenceRootHash` is the core binding: verification must match the referenced evidence package's `rootHash` to prevent evidence substitution.

Additional types: `linkedEvidenceId` is the bound package's `packageId` (UUID v4 string); `parties[].name` string, `confirm` boolean, `signedAt` per C4; `canvasSnapshotHash` per C1 / C9; `sealNote` string.
After sealing the canvas is locked; any change requires a new `packageId`.

### 4. fieldseal-bundle-v0.1 `bundle-index.json`

```json
{
  "spec": "fieldseal-bundle-v0.1",
  "bundleId": "uuid-v4",
  "rootHash": "sha256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "createdAt": "2026-11-11T11:00:00Z",
  "items": [
    { "packageId": "xxx", "type": "evidence", "hash": "sha256:xxx" },
    { "packageId": "xxx", "type": "signature-record", "hash": "sha256:xxx" }
```

> The bundle uses `bundle-index.json` as its root manifest (equivalent to the `manifest.json` role in General rule 2).
> Child `.zip` files are stored in the bundle, each carrying its own `manifest.json`.
> `items[].packageId` must equal the child manifest's `packageId` / `bundleId`; `items[].hash` follows C8.

## fieldseal-evidence-v0.1 compatibility

1. **Read-only compatibility**: `verify` must fully verify v0.1 packages; it must not auto-upgrade, backfill fields, or rewrite the package.
2. **Field difference**: v0.1 contains only `spec` / `packageId` / `rootHash` / `createdAt` / `files`; v0.2 adds `captureTsDevice` / `gps` / `note` / `tags` / `mp4SanityCheck`. v0.2 is a superset of v0.1; `files[]` element structure is identical.
3. **Same hash algorithm**: both versions compute rootHash identically (C2 + C3), with no migration recomputation difference. The `spec` literal differs, so the same content under a different version yields a different rootHash.
4. **Default creation**: PWA capture produces v0.2 by default; v0.1 exists for legacy packages and minimal test fixtures, and can be explicitly selected on the capture page.
5. **Cross-package binding unchanged**: `fieldseal-signature-v0.1` can bind a v0.1 or v0.2 evidence package; binding always uses the package's `packageId` + `rootHash`, independent of version.
6. **Bundle compatibility**: `fieldseal-bundle-v0.1` `items[]` may contain v0.1, v0.2, and signature children; `type` still only distinguishes `evidence` / `signature-record`.
7. **Unsupported policy**: an unknown `spec` literal (including future versions) is always `invalid_spec`; never guessed.

## Verification rules

1. Read `manifest.json` from the ZIP and check that the spec version is supported.
2. Canonicalize the manifest, hash it, and compare with `rootHash`.
3. Walk `files`, hash each file's bytes, and compare one by one.
4. Signature-record packages: when the caller supplies the linked evidence package, compare `linkedEvidenceRootHash`.
5. Bundle packages: read `bundle-index.json`, walk every child, and verify each recursively.
6. Fixed top-level result fields: `coreResult: "ok" | "tampered" | "invalid_spec" | "missing_linked_package"`.
7. Extra information goes in `pluginExtras` and never enters the root hash.

Refined decisions (same rules; defines the decision order):

| Situation | coreResult |
| --- | --- |
| Unsupported spec literal / invalid JSON / missing field / extra field / wrong type | `invalid_spec` |
| Signature package declares `linkedEvidenceId` but the evidence package is not supplied and not found in the bundle | `missing_linked_package` |
| `rootHash` mismatch / `files[].hash` mismatch / declared file missing / undeclared root entry | `tampered` |
| `linkedEvidenceRootHash` ≠ the linked evidence package's `rootHash` | `tampered` |
| `items[].hash` ≠ child bytes hash / `items[].packageId` ≠ child packageId / any child fails recursively | `tampered` |
| Everything passes | `ok` |

Priority: `invalid_spec` > `missing_linked_package` > `tampered` > `ok`.

CLI (`--json`) fixed top-level shape:

```json
{
  "coreResult": "ok",
  "packageType": "evidence",
  "packageId": "xxx",
  "rootHash": "sha256:xxx",
  "pluginExtras": {}
}
```

`packageType` ∈ `evidence` | `signature-record` | `bundle`. `packageType` / `packageId` / `rootHash` / `pluginExtras` are **verification output fields**, not part of any manifest schema.

## Packaging rules

1. Original media is written into the ZIP as-is; no transcoding, no quality reduction.
2. `manifest.json` sits at the ZIP root.
3. Auxiliary snapshots and previews live under `/aux/` and are marked auxiliary.
4. File names use only English letters, digits, and hyphens; no Chinese or special symbols.

Details: entry names per C5, writing per C6, `aux/` and the hash tree per C7 / C9.

---

## Optional TSA rules

- Upload only the root hash string; never upload a file.
- Use native `fetch`; the user supplies the TSA server URL.
- Off by default; no automatic request.

> Aegis is likewise an optional external system: the kernel contains no Aegis code, only a reserved hash-digest push interface (optional Step 6).

## Prohibitions (project iron rules)

1. No third-party runtime dependency in the trusted core (`cli/core`, `pwa/core`); neither directory may contain `package.json`, and neither runs `npm install`.
2. No third-party pdf / zip / crypto library.
3. No automatic upload of original photos, videos, or signature originals to any external service.
4. No built-in or implied promise of an eIDAS qualified electronic signature.
5. No private addition, modification, or deletion of manifest fields; `pluginExtras` never enters a manifest.
6. `pwa/helpers` logic never participates in root-hash computation.
7. No external code: third-party libraries, copied/pasted or vendored source, CDN or remote scripts, generator output. Only platform-native APIs are exempt (see C12). All source is 100% hand-written.
